## Completed continuation and validation

The commits repair cached solution validation without modifying scoring/session code, align MPoTD docs with first-correct v2, accept validated Discord exclusion lists, recheck bot/requester/origin permissions at return, handle lookup failure, remove request-argument logging, and assemble up to five independently verified Discord passages. Synthesis remains extractive: unsupported paraphrases are not accepted as facts.

Opt-in provider selection and separate credentials/capabilities now connect to inference. A narrow local allowlist preserves casual identity/interaction; harder requests require the external backend. Sensor outages route conservatively. Bounded provider retries, response/tool parsing, unknown envelope rejection and successful-fetch evidence state have regression coverage. Both providers receive the unchanged Aleph persona and trusted creator context. Defaults remain single-backend; no secrets were changed.

Final validation: **285/285 Bun tests across 27 files**, **4/4 Python tests**, `bun run check`, `bun run build`, and scoped `git diff --check` passed with Bun 1.4.2 and the existing Python virtual environment. This includes synthetic migration/history preservation tests, PDF raster fixtures, practice concurrency and mocked Discord/provider checks. Final SHA-256 checks matched all eight training/aleph files and both tracked service `.bak` files to the pre-edit baseline. The seven original uncommitted training entries remain outside development commits.

No new migrations, dependency changes or slash definitions were introduced. No production data access, push, command registration, bot start, PM2 restart or deployment occurred. See [deployment plan](deployment-plan-2026-09-26.md).
