# Aleph-Zero reliability

The reported production model is Phi-4-mini-instruct-GGUF Q4_K_M through llama.cpp, with native tool and dedicated reasoning support disabled by its template. No reasoning flags are changed. `INFERENCE_NATIVE_TOOLS=false` is the default in the service configuration and examples: the host accepts a bounded JSON tool request, executes only its existing allowed tools, and feeds the result back. Set this option to `true` only for a separately validated native-tool backend. Aleph-Zero's persona remains independent of the model vendor; no cutoff date is configured.

`src/service/retrieval-policy.ts` requires retrieval for explicit verification, current information, specific factual questions, recognized proper names, and exhaustive factual lists. Simple conversation, common timeless educational questions and ordinary math avoid automatic search. Exact entity strings are included in the query and must appear in evidence; names are not spelling-corrected. A short referential follow-up uses the previous question for routing. This is a conservative heuristic, not a universal entity recognizer.

The runner executes mandatory retrieval before asking the model for an answer. Empty, failed, or entity-mismatched results produce an explicit inability-to-verify response. Uncertain drafts and attempted citations trigger retrieval too. Once search/source verification is requested, a failed tool cannot fall back to a memory-only factual answer. Limits remain six model rounds, four calls per round and 24 total tool operations; search is additionally capped at two calls. Cancellation and the existing overall job timeout still apply.

Search uses the configured Tavily key and safe public HTTPS fetching. Evidence is bounded to 12 sources and 6,000 characters. The model may select exact excerpts and source IDs, but cannot supply final factual prose or invent citation URLs. The host validates each excerpt against the retrieved text and renders links from its own ledger. Two invalid final attempts end in refusal. Exhaustive requests explicitly warn that results are a subset. This intentionally conservative output may refuse or quote sources instead of producing a fluent synthesized answer. Source accuracy, relevance, omitted context and conflicting accounts still require judgment; exact excerpt matching does not prove truth or completeness. Existing DNS pinning, redirect checks, byte/time limits and untrusted-tool-data handling remain in force.

The stuffed-toy regression has a narrow deterministic solver for the three-inventory, disjoint different-character pair problem. It constructs and verifies both a failing selection and a sufficient matching bound. It is not a general proof checker for arbitrary competition mathematics.

Delivery uses its existing four-second polling and unchanged-status suppression. Progress names describe actual operations: thinking during model generation, searching during search, reading a source during fetch, calculating/plotting during math tools, examining image during image preparation, and preparing answer before return. No hidden reasoning is exposed.

## Manual rollout checks

The search adapter calls the official [Tavily Search API](https://docs.tavily.com/documentation/api-reference/endpoint/search) directly with Bun's fetch. It uses basic general search, at most five results, no automatic parameter upgrades, generated answers, raw content or images, and no automatic retries. Tavily `content` becomes the existing bounded `description` evidence field; generated answers are never consumed. Existing host search budgets and exact-name queries remain unchanged. Automated provider tests use only mocked requests and fixture credentials; they do not verify live Tavily authentication.

Production needs `TAVILY_API_KEY` in the existing `.env.ai.production` secret file (shared production environment mechanism). Keep its value private. After a deliberate manual release/restart of the study service, run one tester-only factual question and confirm cited results, then ordinary conversation and the stuffed-toy problem and confirm no search usage for those prompts. Check Tavily's usage dashboard for unexpected repeated requests. In development, also test a missing/invalid key and confirm explicit refusal. No Discord command update is needed for this provider change.

- Run `bun test`, `bun run check`, `bun run build`, and the Python tests before reviewing a release. `BOT_ENV=development bun src/index.ts --check-startup` checks development Discord login and exits before starting background delivery/QOTD.
- Configure `TAVILY_API_KEY` in the appropriate service environment on the host. Mandatory retrieval will refuse without working search. Keep native tools disabled for the reported Phi template; do not change llama.cpp reasoning flags.
- Review, commit and push, then use the existing manual commit-SHA deployment procedure. Restart both the study service and Discord bot for these changes. No deployment or secret-file modification is part of this change.
- Separately register the updated command definitions when ready to remove the obsolete command from Discord's UI. Startup and deployment do not register commands. Unused historical SQLite tables are left untouched; no destructive cleanup is needed.
- With the real backend, manually check the Pax Silica, Eternal Towers of Hell and Hatsune Miku questions, offline-search refusal, JSON tool formatting, the stuffed-toy proof, status timing, tester-only access and QOTD/moderation. Mocked orchestration tests do not establish live Phi answer quality. Keep the inference and study endpoints private.
